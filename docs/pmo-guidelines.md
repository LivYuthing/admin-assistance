# PMO Guidelines - คู่มือและแนวทางปฏิบัติ

## 1. วัตถุประสงค์ของ PMO

PMO (Project Management Office) มีหน้าที่:
- กำหนดมาตรฐานและกระบวนการบริหารโครงการ
- สนับสนุน Project Manager ในทุกโครงการ
- ติดตามและรายงานสถานะโครงการต่อผู้บริหาร
- จัดการความรู้และ best practices ขององค์กร

## 2. กระบวนการบริหารโครงการ

### 2.1 การเริ่มต้นโครงการ (Initiation)
1. จัดทำ Project Charter
2. ระบุ Stakeholders
3. ขออนุมัติจาก Sponsor

### 2.2 การวางแผน (Planning)
1. จัดทำ Project Plan
2. จัดทำ Risk Register
3. กำหนด KPIs และตัวชี้วัด
4. อนุมัติแผนโครงการ

### 2.3 การดำเนินงาน (Execution)
1. ดำเนินงานตามแผน
2. จัดประชุม Weekly Status Meeting
3. จัดทำ Status Report รายสัปดาห์/รายเดือน
4. อัปเดต Risk Register

### 2.4 การติดตามและควบคุม (Monitoring & Controlling)
1. ติดตาม KPIs
2. จัดการ Issues และ Risks
3. รายงานความคืบหน้าต่อผู้บริหาร

### 2.5 การปิดโครงการ (Closure)
1. ส่งมอบ Deliverables
2. จัดทำ Lessons Learned
3. ปิดโครงการอย่างเป็นทางการ

## 3. มาตรฐานเอกสาร

### 3.1 การตั้งชื่อไฟล์
```
[ProjectCode]-[DocumentType]-[Version]-[Date].md
ตัวอย่าง: PRJ001-StatusReport-v1.0-20260416.md
```

### 3.2 Version Control
- v0.1, v0.2 = Draft
- v1.0 = Approved
- v1.1, v1.2 = Minor update
- v2.0 = Major revision

### 3.3 Approval Process
| เอกสาร | ผู้จัดทำ | ผู้ตรวจสอบ | ผู้อนุมัติ |
|--------|---------|-----------|---------|
| Project Charter | PM | PMO | Sponsor |
| Status Report | PM | PMO | - |
| Risk Register | PM | PMO | Sponsor (High Risk) |

## 4. การประชุม

| การประชุม | ความถี่ | ผู้เข้าร่วม |
|---------|--------|-----------|
| Project Kick-off | ครั้งเดียว | ทีมโครงการ + Stakeholders |
| Weekly Status | รายสัปดาห์ | PM + ทีมโครงการ |
| Steering Committee | รายเดือน | PMO + Sponsors + PM |
| Project Closure | ครั้งเดียว | ทีมโครงการ + Stakeholders |

## 5. ติดต่อ PMO

สำหรับคำถามหรือความช่วยเหลือ ติดต่อทีม PMO ได้โดยตรง
